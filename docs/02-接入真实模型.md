# 接入真实模型

> 默认的 `MockLLM` 是为了让你免费跑通流程。这一篇讲：想换成真模型，要改什么、注意什么。

---

## 一、只需要四个环境变量

`helloagent` 里所有模型调用都走 OpenAI 兼容的 `/chat/completions` 接口。换成真实模型，**不改一行代码**，只设环境变量：

| 变量 | 说明 |
|---|---|
| `HELLOAGENT_BACKEND` | `mock`（默认）或 `openai` |
| `HELLOAGENT_API_KEY` | 你的密钥 |
| `HELLOAGENT_BASE_URL` | 接口地址，默认 OpenAI 官方 |
| `HELLOAGENT_MODEL` | 模型名 |

### 以 DeepSeek 为例

```powershell
# PowerShell
$env:HELLOAGENT_BACKEND="openai"
$env:HELLOAGENT_API_KEY="sk-你的密钥"
$env:HELLOAGENT_BASE_URL="https://api.deepseek.com/v1"
$env:HELLOAGENT_MODEL="deepseek-chat"
```

```bash
# Bash
export HELLOAGENT_BACKEND=openai
export HELLOAGENT_API_KEY=sk-你的密钥
export HELLOAGENT_BASE_URL=https://api.deepseek.com/v1
export HELLOAGENT_MODEL=deepseek-chat
```

然后照常运行：

```bash
python lessons/01_minimal.py
```

### 其他常见服务商

| 服务商 | BASE_URL | 模型名示例 |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 本地 Ollama | `http://localhost:11434/v1` | `qwen2.5:7b` |
| 本地 vLLM | `http://localhost:8000/v1` | 你部署的模型名 |

> Ollama / vLLM 通常不校验密钥，随便填一个非空字符串即可（本仓库要求 API_KEY 非空才会启用 openai 后端）。

## 二、换到真模型后，行为会变的地方

### 1. `MockLLM` 的"规则"没了

Mock 用正则匹配决定输出，真模型靠语义判断。所以：

- 第 1 课里"哪些问题触发工具"的规律会变；
- 你需要把工具 `description` 写得更具体，才能稳定命中。

### 2. ReAct 的格式契约要更硬

真模型不一定严格输出 `Thought: / Action: / Action Input:` 三行。常见问题：

- 用中文写"思考："而不是 `Thought:`；
- `Action Input` 里不是合法 JSON；
- 一次输出多个 Action。

本仓库的 `_RE_*` 正则比较宽松（匹配 `Thought:`），但如果你遇到解析失败，可以：

```python
# 在 prompt 里加一句更硬的约束
"只允许输出以下三种标签，不要用中文标签名：Thought: / Action: / Final Answer:"
```

更工程化的做法是改用 **function calling**（OpenAI 的 `tools` 字段），由接口保证结构化输出，不靠正则解析。本仓库为了让原理透明，故意用了「提示 + 正则」的原始方式——你正好可以对比这两种做法。

### 3. 成本与限流

- 每轮对话都会把历史发过去，**历史越长越贵**；
- `max_steps` 直接决定最坏情况下的调用次数；
- 加个简单的重试与超时（`OpenAILLM` 里已有 60 秒超时）。

## 三、动手改：从「一次调用」到「反思再改」

接上真模型后，最有价值的一个练习是：**让 Agent 检查自己的输出**。

思路（不用改核心代码，新建一个脚本即可）：

```python
from helloagent import SimpleAgent, ReActAgent, MockLLM

llm = ...                       # 你的真实模型
worker = ReActAgent(llm=llm)
critic = SimpleAgent(llm=llm)   # 同一模型，换个提示扮演"审稿人"

answer = worker.run("查一下景德镇天气，并判断适不适合户外演出")
review = critic.run(f"请检查这段回答是否有事实错误或遗漏：\n{answer}")
print(review)
```

这就是「生成—评估」模式，也是很多 Agent 框架里 Reflect / Critique 的雏形。

## 四、安全提醒

1. **不要提交密钥。** 本仓库的 `.gitignore` 已排除 `.env`，但请自己也确认一遍。
2. **工具要限权。** 一旦工具能读写文件、执行命令，就等于把机器的控制权交给了模型输出。本仓库的 `calculator` 用 AST 白名单而非 `eval`，就是这个原因。
3. **给循环设上限。** `max_steps` 不只是省钱，也是防止失控。
